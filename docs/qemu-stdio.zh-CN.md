# 消除 QEMU 端口依赖，与 relay 端口租约（v0.4 #1）

> **状态：提案。** 本批次不写代码。它回答在这个代码库里「消除 QEMU 端口依赖」应该指什么、统一的
> 端口租约是什么，以及两者与当前发布的 TCP 传输如何共存。原先的「方案 3」提法已舍弃：本仓库没有
> 任何地方记录过那份选项清单，读者无从查证。

## 1. 现状（以代码为准的事实）

- **QMP 走 TCP**：`QmpEndpoint::tcp(host, port)` 渲染为 `-qmp tcp:host:port,server=on,wait=off`
  （`sandbox/src/platform.rs`）。qmp_capabilities / stop / cont / quit 都在这条通道上。
- **串口走 TCP**：`SerialEndpoint::tcp(host, port)` 渲染为
  `-serial tcp:host:port,server=on,wait=on` —— `wait=on` 表示 QEMU 阻塞到宿主连上为止，这正是
  "我们的读取线程接好之后 guest 才起机"的机制。
- **端口**来自 `sandbox::relay` 的端口租约（`lease_local_port` / `lease_local_ports`，v0.4 #1）：
  bind `127.0.0.1:0`，读出系统分配的端口，然后**保留**它 —— 连同已绑定的 listener —— 直到调用方交接
  并释放租约。交接才是让 QEMU 能绑定的那一步，所以在交接与 QEMU 绑定之间仍存在与**其它进程**的竞争
  （*TOCTOU*）。租约消除的是：本程序内部把同一端口发给两个持有者，以及在交接之前别人对它的可及性。
- **当前的缓解手段是重试，不是设计改动**：`start_vm` 用新端口重试 3 次（`agent/src/tools.rs`），
  快照恢复重试 3 次（`sandbox/src/vm.rs`），而 sandbox 测试辅助的 `two_free_ports()` 用进程级守卫
  避免同一 binary 内两个线程拿到同一个端口。v0.3.0 的「快照中继端口重试」正属于这一类**局部缓解**。
- **文档里已有两条约束直接否掉了最朴素的 stdio 方案**：`ENVIRONMENT.md` 写明串口必须用 **TCP socket
  或 file**，**不用** `mon:stdio`（交互式、无法脚本化）；`sandbox/README.md` 记着「不使用 Unix domain
  socket，不使用 `mon:stdio`」。所以这里的"stdio"不可能指 `-nographic` + `mon:stdio`。
- **快照恢复额外需要端口**：QEMU 以 `-incoming tcp:127.0.0.1:…` 启动，由我们的 relay 连上去把 `.mig`
  推给它（`sandbox/src/vm.rs`、`sandbox/src/relay.rs`）。
- **file 形态的串口已经支持**（`SerialEndpoint::file`），只是串口**读取器**目前只为 TCP 变体接线。

## 2. 「消除端口依赖」指什么

v0.4 路线图的这一条（`PROJECT_CONSTITUTION.md` §10）原文是：*「消除 QEMU 的 TCP 端口依赖，与统一的
relay 端口租约。」* 此前的措辞叫它「QEMU stdio（方案 3）」—— 而本仓库里**从未**列出过方案 1/2/3
（没有文档、没有 changelog、没有注释），所以换成了一个说清了改动是什么的名字。

本提案采用的解读（实现前请确认或纠正）：

- **QMP 改走子进程自己的标准流**：QEMU 支持 `-qmp stdio`；作为父进程我们已经持有子进程的管道，于是
  QMP 变成我们自己读写的管道。控制通道**不再有端口，也就没有 TOCTOU**。
- **串口也不再需要端口**：改用 chardev / file 形态（端点变体已支持），并为它补一个读文件的读取器。
  这样路线图那句"彻底消除 QMP **与串口**的 TCP 端口依赖"才可以做到，且不碰 `mon:stdio`。
- **剩下仍需端口的部分 —— 快照迁移的监听 —— 收进同一个租约**（§3）。

有一条机制上的事实要先说清：一个进程只有一个 stdout，所以 QMP-over-stdio 与 stdio 串口**不能同时**
使用；串口必须走另一条通道。这是机制约束，不是偏好。

## 3. relay 端口租约

**粒度：每个宿主进程一个租约。** 不是每次 run 一个、也不是每套 VM 配置一个。理由：

- VM 比 run 长寿（宿主持有的 `vm_slot`），而快照中继的生命周期是一次迁移、不是一次 run。
- 要防的失败是**同一个程序的两个部分**在同一时刻选中同一个端口（或某部分还持有而另一部分又去选）。
  进程级分配器正好覆盖这个问题域；"全局/系统级"租约需要我们没有的权限，而且应用开第二个实例就失效。
- 今天的缓解在测试里已经是进程级的（sandbox 测试辅助的 `two_free_ports()`）——租约只是把测试里已经
  在做的事推广到生产代码。

租约的形态（v0.4 #1 已实现）：一个分配器，(a) bind `127.0.0.1:0` 让系统挑一个空闲端口，(b) 在持有者
仍需要它时把端口记为**被持有**，(c) 在第一个持有者释放之前不再把同一端口给第二个持有者。它**本身
不能消除** TOCTOU —— listener 仍然要在 QEMU 绑定前放开，只是尽可能地晚 —— 所以它是对竞争窗口的
**收窄**加上"重试只发生在一处"，不是证明。真正把端口从等式里拿掉的是 QMP 改 stdio 那一步。

## 4. 与快照中继的交互

- 恢复路径是唯一必须让 **QEMU 自己**监听的一条：`-incoming tcp:` 让 QEMU 监听，我们的 relay 去连并推
  数据。所以端口必须在 QEMU 启动前选定，然后由 QEMU 去绑定 —— 与 QMP/串口同样的 TOCTOU。
- 在租约下，该端口从分配器取、迁移结束（成功或失败）即释放，于是快照恢复不再可能与 QMP/串口的端口选择
  撞车，也不会与并发的第二次恢复互抢。
- 现有的三次重试**保留**：租约收窄竞争，重试兜住剩下的；在 QEMU 能接受一个"预先绑定好的 socket"之前
  （用今天的参数它不能），两者都需要。

## 5. 向后兼容

- **保留 TCP 路径。** 它是当前发布的传输、是所有既有测试覆盖的路径，且项目平台定位就是"Windows +
  TCP"；直接换成 stdio 等于重写，而唯一受益者只是端口竞争。
- **先让 stdio 可选**（配置开关，默认关闭），等 e2e 套件两条路径都跑一段时间后，再考虑在更晚的版本
  里把它设为默认。
- `.mig` 快照、审计事件与 run 指纹都不受影响：传输方式不属于任何持久化格式。（指纹目前**不**记录
  传输方式；如果传输变得可配置，那么它应该被记录 —— 一次 run 的结果依赖于它。）

## 6. 分阶段

**v0.4（已授权、已实现）：只做租约。** 不动协议，不涉及 stdio。

1. 已完成：在 `sandbox::relay` 里放一个记录「已持有端口」的分配器（`lease_local_port` /
   `lease_local_ports`）；`start_vm`、快照恢复与宿主自己的端口选择都从它取端口，并在 QEMU 启动前
   才交接。改动小、可测、不动协议。
2. 现有的三次重试原样保留，作为兜底。
3. 已完成：`sandbox/tests/relay.rs`（并发租约不会重复、释放后号码归位、交接前 listener 挡住别人）与
   `sandbox/src/relay.rs`（耗尽时给出明确错误）的测试；既有的端口竞争 / 重试测试保持通过。

**v0.5：把 QMP 与串口从 TCP 上摘下来。** QMP 走 stdio，放在配置开关后面；串口走 file 变体并补上
对应的读取器；再加一条“用这种方式起 guest”的测试；再往后才是把 stdio 设为默认、退役重试。v0.4 授
权的 `sandbox` 改动范围是**端口租约**，stdio / file 改造**不在其中**，已顺延到 v0.5。

## 7. 会碰哪些 crate

- **`sandbox` —— 会碰。** 端点（`platform.rs`）、VM 的 QMP/串口接线（`vm.rs`）、中继（`relay.rs`）。
- **`agent` —— 会碰，但很小。** `start_vm` 构造 VM 配置，需要把传输方式透传下去。
- **`host` —— 会碰，但很小。** 恢复路径自建配置，串口转发器读串口流。
- `audit` —— 不碰。

因为会碰 `sandbox`，这一项需要项目对该 crate 的专门授权。
