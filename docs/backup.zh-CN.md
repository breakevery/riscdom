# 备份与可移植性

**状态** v1.0 规范（M7e；于 M7e 的规格修正批 AW 修订）｜ **日期** 2026-09-29 ｜ **面向读者** 运维者，以及必须
搬动一个节点 —— 或必须证明它能被搬动 —— 的人。

**本文是什么。** [decisions §19](decisions.zh-CN.md) 已定：一个 **`riscdom-backup`** CLI 把审计存储、快照与
凭据**导出一件可搬走的包**，而「该包就是可移植性的单位；恢复一个节点的历史与身份不需要包外的任何东西」。
本文写下那个包里装什么、怎么造、怎么恢复、以及它刻意不做什么。它是一份**规格**；工具在后续批次。

**为什么这是 v1.0 的条目。** §19 自己的理由：*能走，才是敢留的前提。* 一个搬不动的节点，就是运维者被它
挟持的节点 —— 所以「一个文件装下全部、随时能走」是一条产品属性，不是事后补的。

## 1. 一个节点由什么构成

一个节点的持久状态是一个小而封闭的集合，且它**分裂在两个根**上：节点被赋予的**数据目录**，与它所工作的
**workspace 里的 `.riscdom/` 目录**。**两个根都是节点状态；两者都在包内。** 恢复所需的一切都在这张表上；
不在这里的，都是节点重启会自行重建的运行时状态（[config-schema.md](config-schema.zh-CN.md) §5）。

### 1.1 数据目录（`<data-dir>`）

| 状态 | 住在哪 | 标记 |
|---|---|---|
| 设置 | `<data-dir>/settings.json` | `version` = **2** |
| 会话存储 | `<data-dir>/sessions.db`（SQLite） | `PRAGMA user_version` = **1** |
| 控制平面 token | `<data-dir>/token` | 无 —— 一行 hex，做形状检查 |
| 节点身份 | `<data-dir>/node.key`，**或** OS keyring | `schema_version` = **1** |
| 同侪表 | `<data-dir>/peers.json` | `schema_version` = **1** |
| 房间表 | `<data-dir>/rooms.json` | `schema_version` = **1** |

### 1.2 workspace 的 `.riscdom/`（`<workspace>/.riscdom/`）

| 状态 | 住在哪 | 标记 |
|---|---|---|
| 审计存储 | `<workspace>/.riscdom/audit.db`（SQLite，**WAL**） | `PRAGMA user_version` = **1** |
| 快照 | `<workspace>/.riscdom/snapshots/<device>/<id>/` | — |

**为何分裂重要。** 数据目录是节点自己的；workspace 是节点所工作的**项目**，而 `.riscdom/` 是节点在其中的
隐藏一角。一个只读数据目录的备份会**不带任何历史、不带任何快照** —— 这就是 §2 要读两个根的原因。在桌面上
两者同住一个 app-data 目录之下的两个位置（`<app-data>/` 与 `<app-data>/workspace/.riscdom/`），但它们
是两个独立输入，工具两个都取。

### 1.3 什么不是节点状态

- **`toolchain/` 与 `qemu/`** 是节点可以再次取得的下载物；包不带任何 toolchain。
- **workspace 里的项目文件**是 AI 的工作产物，不是节点状态：包从 workspace 只取 `.riscdom/`、不取别的。
- **`.bak` 文件**是迁移逃生口，不是恢复所需的状态（§2）。

### 1.4 凭据，以及那一条诚实的限度

API key 与服务器 token 住在 **OS keyring** 里、不在文件里 —— 所以 §19 的「不需要包外的任何东西」意味着
它们**在包内**同行。**OS keyring 没有枚举 API**：`keyring` v3 按 service 与 account 查找一条凭据，永远
无法列出里面有什么。于是工具不问「里面有什么？」，而是从 `settings.json` **反推它预期的账户名**、只读
那些：

| 凭据 | 账户名 | 从哪反推 |
|---|---|---|
| 提供方 API key | `llm-api-key:<executor_id>:<provider_id>` | `LocalSettings.executors[]` 与 `llm_configs[<executor>].provider_id` |
| 提供方 key（legacy） | `llm-api-key:<provider_id>` | executor 之前的拼法，仍为迁移而读 |
| 内网服务器 token | `remote-token:<host>` | `NetworkSettings.remote_url` |

**反推不出来的，会被报告、绝不静默漏掉。** 一个其 executor 已不在 `settings.json` 里的 key，或一个其存储
host 已与 `remote_url` 不符的 token，无法被点名 —— 而工具不猜。它把**每一个反推不出来的条目**列进导出报告与
清单，好让运维者看见缺口、可以手工补上。**那份清单就是这个包唯一声明的包外依赖：** §19 的「不需要包外的
任何东西」对工具能点名的一切成立，而例外被说出来、不被藏起来。这是本项目对待一条真实限度的习惯 —— 直说，
就像 [connection.md §3.2](connection.zh-CN.md) 对待一条重启即丢失的重放记录那样 —— 而不是粉饰过去。

标记以 [api-compatibility.md §6](api-compatibility.zh-CN.md) 为准；这里的表是同一集合从**「一次备份必须带
什么」**这个角度看到的。

## 2. 导出

**一条命令、一个文件。** `riscdom-backup export` 读取 §1 的状态，写出**单个文件**，惯例命名为
`riscdom-backup-<node_id>-<timestamp>.rdbak`。

- **包是加密的，而工具从不持有密钥。** 导出从**运维者**取一个**口令**，在其下写出包（对归档做认证加密）。
  该口令**绝不被工具写到盘上、绝不放进命令行、绝不打印** —— 与本项目其它地方对待凭据的是同一条规矩。**不
  提供未加密的包**：那会把一把 Ed25519 私钥和一组 API key 放进一个明文文件，恰是备份的反面。
- **包里、在加密之下装着：** §1 中**存在**的每个文件，按它盘上的布局摆放 —— 数据目录的条目与 workspace 的 `.riscdom/` 条目，各在自己的根下（于是恢复只是把东西放回它们来的地方）—— 加上 §1.4 反推出来的 keyring 条目。**一份清单**在包的根上，逐条列出每个条目的名字、大小与内容哈希，并记下节点的 `node_id`、导出的时刻、各格式的标记、以及 §1.4 里那份反推不出来的条目清单 —— 于是恢复在写任何东西之前就能说出自己手上是什么。
- **审计存储是一致地拷贝，不是逐字节拷贝。** `audit.db` 是 **WAL** 且被多个进程同时打开，所以单对文件做
  字节拷贝会漏掉仍在 `-wal` 里的帧（[api-compatibility.md §6](api-compatibility.zh-CN.md) 说的正是这件事，
  也是审计存储没有 `.bak` 的原因）。因此导出经 SQLite **自己的一致性路径**取存储（备份镜像或
  `VACUUM INTO`），绝不做原始文件拷贝。**一份审计存储被撕裂的包，比没有包更糟**，因为它看起来像历史、
  却不是。
- **迁移逃生口不带。** `settings.json.bak` 与 `sessions.db.bak` 是迁移在出错那一刻留下的字节；它们不是恢复
  所需的状态，包把它们排除在外。
- **不读任何节点本不会读的东西。** 导出只读 §1 的两个根与 keyring，别的什么都不读；它不对外拨号，也不需要
  网络。

## 3. 导入

**包被恢复进一个数据目录**，随后节点在它上面启动。`riscdom-backup import --from <file> --into <data-dir>`。

- **它拒绝静默覆盖。** 导入到一个已经持有某节点状态的数据目录，除非运维者明确说了，否则被拒；§19 的包是
  一次**搬动**，而一次悄悄替换掉节点的搬动，是把两段历史变成一段的方式。
- **较新的格式被拒、不被猜测。** 恢复的目标是一个**同版本或更旧**的节点：每个格式的标记严格按
  [api-compatibility.md §6](api-compatibility.zh-CN.md) 的规定检查，来自**运行中节点之后**的文件以
  `data_too_new` 被拒 —— 什么都不读、什么都不写。正因如此清单记下标记：恢复能在碰任何东西之前告诉运维者
  「这个包来自更新的节点」。
- **凭据回 keyring。** 包里的 API key 与服务器 token，在目标机器上按 §1.4 反推出的同一批账户名重新录入 OS
  keyring；它们绝不作为文件写进数据目录（那正是 [decisions §6](decisions.zh-CN.md) 的 keyring 规矩要防的
  错误）。`node.key` 在源节点把它放在数据目录时写进数据目录，放在 keyring 时写进 keyring。
- **节点身份随它一起回来。** 因为 `node.key` 在包内同行，一个被恢复的节点就是**网络认识的那个同一个
  节点** —— 同一个 `node_id`、同一个指纹 —— 而不是一个只是持有旧数据的新节点。

## 4. 可移植性的单位是整个节点

§19 的影响是刻意绝对化的：**包是全有或全无**。没有选择性导出（「只要审计日志」、「只要设置」），因为
部分包会违反「不需要包外的任何东西」—— 一个由自身一部分恢复来的节点，是一个历史与身份不匹配的节点。
**唯一**声明的例外是 §1.4 那份工具点不出名的 keyring 条目清单；它被报告，绝不被悄悄略去。
想要其中某一块数据的运维者，用已有的读取工具（[audit/README.md](../audit/README.md)、控制平面的读路由），
而不是一份半备份。

## 5. 一次备份怎么被核对

- **清单就是核对。** 它逐条的内容哈希让导入在写任何东西之前先验证包完好，它记下的标记让它验证包不是来自
  更新的节点。失败会被报告，绝不被绕过。
- **恢复后审计链自证。** 历史的完整性是链自己的事：`verify_chain` 定位第一个断裂的事件
  （[audit/README.md](../audit/README.md)），所以恢复可以以「确认链完好」收尾 —— 一个包自身哈希给不了的
  独立检查。
- **先 dry-run。** 导入可以**不写任何东西**就报出清单、节点身份与格式标记，于是运维者在真正恢复之前先
  看清自己要恢复的是什么。

## 6. 不覆盖什么

- **没有增量或差分备份。** 一个包就是整个节点（§4）；第二个包是另一个整个节点。更聪明的做法是日后的决策，
  不是默认的功能。
- **没有调度、没有目的端。** §19 描述的是一件**运维者运行的**工具，产出一个由运维者放到某处的文件。节点
  从不按定时器自我备份、也从不往任何地方上传 —— 把一个节点的凭据发给某项服务，就是项目在运营一项服务，
  正是 [roadmap §1](roadmap-v1.0.zh-CN.md) 红线所禁止的。
- **没有密钥托管、没有口令找回。** 口令是运维者的；工具无法找回它，丢了口令就是一个读不了的包 —— 而这
  正是加密它的意义。
- **对运行中节点的实时状态不作承诺。** §2 让*存储*一致；它不会在一条指令中途冻结一台 VM、也不捕获在飞的
  工作。快照以它们本来的文件形态同行；一台活动 VM 的内存是沙箱的事，不是备份的事（快照自身的预算见
  [performance-budget.md](performance-budget.zh-CN.md)）。
- **工具本身** —— 它的确切参数、它的密码选择与它的文件扩展名 —— 属于实现批，对着本文写。
