# 安全模型

**状态** v1.0 规范（里程碑 [M1](roadmap-v1.0.zh-CN.md)）｜ **日期** 2026-09-27 ｜ **基线** v0.9.9
（`3365970`）｜ **受众** 管理员 —— 运行一个节点并为它负责的人。§5（报告漏洞）面向发现漏洞的人。

**本文是什么。** [v1.0 纲领](roadmap-v1.0.zh-CN.md) §6 所要求的六件事中的第五与第六件：**凭据与密钥
管理**，以及**披露政策**。它说明每一份机密住在哪、一个 capability 值多少、以及内核**不**负责什么。它是
[`SECURITY.zh-CN.md`](../SECURITY.zh-CN.md)（对外那份短声明）与
[`docs/control-plane-api.zh-CN.md`](control-plane-api.zh-CN.md) §3（线上）背后的设计。

## 1. 凭据与密钥

- **[已定]** **两类机密，两种算法。** 节点用 **Ed25519** 声明身份；API 访问用**持有者 token**。这里
  没有一样是自己造的：Ed25519 用标准编码（PEM 或 JWK），token 是 OS 随机数的 32 字节 hex
  （[`server/src/token.rs`](../server/src/token.rs)）。
- **[已定]** **私钥默认是文件，钥匙串可选。** 节点私钥住在 `<data-dir>/node.key`、mode `600`
  （Windows 上是一条仅属主的 ACL），或按运营者的偏好住在 OS 钥匙串里。用哪一个属于部署选择，而这个形状
  在它被实现之前就由 [decisions §13](decisions.zh-CN.md) 定下了。
- **[已定]** **轮换多密钥并行。** 一个节点可以发布新密钥、同时旧密钥仍然有效：灰度期两者都能验签，
  于是一次轮换不需要一个「切换日」。
- **[已定]** **撤销是全网且响亮的。** 撤销名单向房间广播，失陷节点在所有地方被踢，而不是只在碰巧注意到
  的地方被踢（decisions §13）。
- **[已定]** **批量导入是 JSON，每个节点一个对象**：`{node_id, addresses[], public_key,
  capabilities, rooms[]}`。它是**配置**文件（纲领 §4 的 `peers.json`）—— 里面是公钥，永远没有私钥。

## 2. 每份机密住在哪

**[已定]** 四类机密，四个住处。表背后的规矩是：**机密绝不待在一个人会去读、去备份、去截图的文件里**，
而非机密偏好也绝不待在钥匙串里。

| 机密 | 它是什么 | 它住在哪 | 生命周期 |
|---|---|---|---|
| **节点身份**（v1.0） | 给本节点消息签名的 Ed25519 密钥对 | `<data-dir>/node.key`、mode 600 / 仅属主 ACL，或 OS 钥匙串 —— 由运营者选 | 与节点同寿；并行轮换，靠广播撤销 |
| **API token** | 控制平面要求的持有者 token | `<data-dir>/token`，一行 hex，`600` 或仅属主 ACL。在服务端**首次启动**时铸出；`--no-auth` 是有文档的免 token 跑法 | 直到运营者删掉该文件（下次启动会铸一个新的） |
| **LLM key** | 模型提供方的 key | **OS 钥匙串** —— service `com.breakevery.riscdom`、账户 `llm-api-key:<provider>`。`DEEPSEEK_API_KEY` 只在启动时被采纳进**内存**，不会被自动写进钥匙串 | 直到运营者更换；钥匙串拒绝时降级为内存，因此可能活不过一次重启 —— 调用方会被告知钥匙串说了什么 |
| **远端节点 token** | 另一个节点的 API token，由*设置 → 网络*使用 | **OS 钥匙串**，账户 `remote-token:<host>` —— 按 host 归档，于是第二个节点不会覆盖第一个 | 直到「断开并改用本机」，那会删掉它 |

- **[已定]** **`settings.json` 不含机密，从来不含。** 该文件自 v0.4 起自己的规矩就是只放非机密偏好；
  LLM key 去了钥匙串，而远端 token 字段在它来得及写出任何凭据之前就被**删除**了
  （[decisions §70](decisions.zh-CN.md)）。
- **[已定]** **读一份凭据不会创造一份凭据。** 设置页可以通过一个只读命令**显示**局域网 token —— 它读
  `<data-dir>/token`，不存在时干净地拒绝（[decisions §67](decisions.zh-CN.md)）；铸 token 仍是服务端的
  事。打开一个页面不得让一份凭据凭空出现。
- **[已定]** **保护不了的 token 会让服务端停下。** 如果平台无法把 token 文件限制为其属主可读，服务端宁可
  拒绝启动，也不端出一个别的账户能读的 token（[`server/src/token.rs`](../server/src/token.rs)）。
- **[已定]** **机密从不进日志、不被回显、不上命令行。** 值只到调用方手上，别处都没有 —— 不进审计链、
  不进消息、不做参数。

## 3. 传输边界

- **[已定]** **开源构建说明文 HTTP，并装一个认证钩子。** 就这些：`Authorization: Bearer <token>`，由
  `Authn` 钩子校验，capability 判定在请求路径里做（[decisions §6](decisions.zh-CN.md)）。
- **[已定]** **TLS 是部署方的责任，而且这条边界是写下来的、不是默认的。** 需要机密性的部署方把节点放在
  TLS 终结器后面；本项目不分发终结器、不假装流量是加密的，并且在本文与
  [`control-plane-api.zh-CN.md`](control-plane-api.zh-CN.md) 里都写明这一点。
- **[已定]** **看板在有人开口之前只绑回环。** 桌面端内嵌 server 绑 `127.0.0.1`，除非「允许局域网」开关
  被打开，而该开关在被勾上的那一刻给出警示 —— 因为它被打开意味着网络上每台设备都能到达本节点，而挡在
  中间的只有 token。
- **[已定]** **协议零新依赖。** 命令与查询用 HTTP，事件流用 SSE，不用 WebSocket —— 单向，没有握手可以
  搞错。

## 4. capability

- **[已定]** **capability 是前置条件，而且它是一个类型。** 路由表的第三列**就是** `Capability` 值，
  于是一条跳过检查的路由根本写不出来（[decisions §6](decisions.zh-CN.md)）；词汇表住在
  [`server/src/auth.rs`](../server/src/auth.rs)，今天有 **32** 条。
- **[已定]** **谁持有什么是部署方的事。** 开源构建给的是机制 —— 每个端点有 capability、每个行动者都被
  检查 —— 而从人到 capability 的映射是部署方的策略。这又是红线 1：内核不决定谁可以做什么，它只让这个
  问题可回答。
- **[已定]** **决定一个请求本身就是一项 capability。** `POST /v0/sandboxes/requests` 可以由任何有权跑
  agent 的人发起（`agent.run`）；*决定*它需要 `sandbox.read` 加上该请求自身动作所蕴含的那个 capability
  （[decisions §36](decisions.zh-CN.md)）。申请与批准是两种权力，词汇表如实说出这一点。
- **[已定]** **本机与远端是两个位置，而八个接线命令知道这件事。** 八个给节点接线的名字在**任何模式**下都
  作用于**本机**（[decisions §71](decisions.zh-CN.md)）—— 服务器不可达的窗口，仍必须能让自己不再做那个
  窗口 —— 而看一个节点（本机或远端）的浏览器是一块**只读看板**：它能看，不能给节点重新接线
  （[decisions §62](decisions.zh-CN.md)）。
- **[已定]** **插件的权力就是它声明的 capability。** 沙箱插件接口复用本模型，而不是另造第二个
  （[decisions §3](decisions.zh-CN.md)）。

## 5. 披露政策

- **[已定]** **渠道。** 通过 **GitHub Security Advisory** 私下报告；绝不走公开 issue。
  [`SECURITY.zh-CN.md`](../SECURITY.zh-CN.md) 是报告者先读到的短版，而本节是它指向的地方。
- **[已定]** **时限。** **48 小时**内确认收到，**7 天**内给出首次评估（严重级别、受影响版本、是否已在写
  修复），并以 **90 天**为协调披露的界线 —— 报告在 90 天后或修复发布时公开，取先到者。
- **[已定]** **CVE。** 对已确认、可利用的漏洞，由维护者申请 CVE 编号；公告随编号一起发出。
- **[已定]** **不设漏洞奖金。** **没有**金钱奖励计划。这是一个非营利的 Apache-2.0 项目：把它明说，比让
  报告者自己去推断更厚道。
- **[已定]** **默认署名，可要求匿名。** 除报告者要求不署名外，公告中会写明报告者。
- **[已定]** **禁发期不是对别人发行节奏的承诺。** 若修复无法在 90 天内落地，报告仍会公开，并写明缓解
  措施。

## 6. 威胁模型：内核对什么负责

**负责**

- **[已定]** 沙箱：执行者的代码跑在一台 VM 里，客机除宿主提供的接口之外，够不到宿主的文件系统与网络。
- **[已定]** 审计链：只追加、哈希相连，且无法经 SQL 重写或裁剪（
  [`audit/src/store.rs`](../audit/src/store.rs) 里的 `BEFORE UPDATE` / `BEFORE DELETE` 触发器是硬保证）。
- **[已定]** §1–§2 的凭据规矩：设置文件里无机密、链里无机密、看一个页面不会铸出凭据。
- **[已定]** 每个端点上的 capability 检查：没有能跳过它的路由。

**不负责**

- **[已定]** 网络的机密性（§3）：明文 HTTP 是开源构建诚实的立场，TLS 属于部署方。
- **[已定]** 模型提供方的行为，或一个 AI 拿着被授予的 capability 决定做什么。内核记录发生过什么，它不做
  监工。
- **[已定]** 敌意的**运营者**：已经持有这台机器上账户的人，能读 token 文件、钥匙串与数据目录。本模型防的
  是别的账户、别的设备、别的节点 —— 不防拥有这台机器的人。
- **[已定]** pin 之外的一切供应链信任：QEMU 从不被捆绑或下载（[decisions §32](decisions.zh-CN.md)），
  RISC-V 工具链是被 pin 并校验哈希的。

## 7. 审计链是信任的根基

- **[已定]** **链就是产品本身。** 每条事件携带前一条的哈希（`prev_hash`）与自己的 `hash`，而 `hash` 在
  表中唯一；UPDATE 与 DELETE 被触发器拒绝，所以日志无法经 SQL 重写或裁剪。
- **[已定]** **它的保证不动。** audit v2 把*语义*扩展到「主链 + 临时段」，并在段首加元数据，**不改哈希
  公式**（[decisions §33](decisions.zh-CN.md)）—— 而由于那次扩展触及红线 5，它需要单独授权
  （`PROJECT_CONSTITUTION.zh-CN.md` §8：*拿不准就先问*）。
- **[已定]** **链里不含机密。** `agent.llm.request` 只记 hash 与 token 数；keyring 事件只记
  `provider_id`（[`SECURITY.zh-CN.md`](../SECURITY.zh-CN.md)）。

## 8. 本文不覆盖什么

- **[已定]** **包的签名与公证。** 安装包与各平台的包均未签名（Windows 上的 SmartScreen、macOS 上的
  Gatekeeper）；那是商业化层的事，写在发行说明里，不在这里。
- **[已定]** **多租户部署。** 一个节点服务一个运营者的工作；租户之间的隔离不是本模型的主张。
- **[待定]** **撤销消息的传输。** §1 说撤销向房间广播；那条广播怎么到达一个当前离线的节点，属于连接层
  的工作（纲领 §4），本文不定。
- **[待定]** **`node.key` 是否在任何部署里都可以住钥匙串。** 钥匙串按设计是可选的，一个没有钥匙串的无头
  服务器必须回落到文件 —— 回落的条件在密钥落地时才定。
