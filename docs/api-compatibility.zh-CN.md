# API 兼容、数据迁移与升级

**状态** v1.0 规范（里程碑 [M1](roadmap-v1.0.zh-CN.md)）｜ **日期** 2026-09-27 ｜ **基线** v0.9.9
（`3365970`）｜ **受众** 发行集成者 —— 在内核之上做产品的人。

**本文是什么。** 一份规矩：什么能改而不弄坏客户端，以及磁盘上的数据怎么活过一次版本更迭。它是
[v1.0 纲领](roadmap-v1.0.zh-CN.md) §6 所要求的「冻结前必须落盘的六件事」中的第一件。它是一份规范：
它说明这次冻结*意味着*什么，好让将来实施的批次有东西可比对。

**它的同伴。** [`error-model.zh-CN.md`](error-model.zh-CN.md)（错误携带什么分类、哪些可重试）与
[`security-model.zh-CN.md`](security-model.zh-CN.md)（密钥、capability、披露）。错误的线上形状与端点表，
规范在 [`control-plane-api.zh-CN.md`](control-plane-api.zh-CN.md) §4 与 §5/§7；本文管的是**关于改动
它们**的政策。

## 1. 冻结什么

- **[已定]** **控制平面的 HTTP 协议。** [`control-plane-api.zh-CN.md`](control-plane-api.zh-CN.md)
  里写下的每一条路径、方法、请求体、应答体、状态码与头，都属于被冻结的面：宿主、集成方与内置客户端
  说的都是它。
- **[已定]** **客户端能观察到的东西。** 事件流的信封与词汇表
  （[`control-plane-events.zh-CN.md`](control-plane-events.zh-CN.md)）、模型可用的工具 schema
  （[`tool-schema-executor.zh-CN.md`](tool-schema-executor.zh-CN.md)、
  [`tool-schema-control-plane.zh-CN.md`](tool-schema-control-plane.zh-CN.md)），以及审计事件词汇表。
- **[已定]** **宿主各 crate 的 `pub use` 面。** 下游 Rust crate 从 `host-core` / `agent` / `sandbox` /
  `audit` 导入的名字是冻结的；它们的内部不是。
- **[已定]** **Rust 内部不冻。** crate 私有的模块、结构体字段、未重导出的函数，任何一个都可在小版本里
  改。「内部」由 `pub use` 清单判定，不由一句注释判定。

## 2. 小版本里允许的变更

- **[已定]** **加一个可选字段**（请求或应答里）。不认识它的客户端忽略它；没收到它的服务端维持今天的
  行为。这正是设置文件自 v0.4 以来遵循的规矩 —— 也是它一直把 `SETTINGS_VERSION` 保持为 **1** 的规矩，直到 v1.0 M2b-1 那次迁移，第一次需要自己版本号的变更）。
- **[已定]** **加一个端点。** `/v1/` 下的新路径天然是增量。
- **[已定]** **加一个 capability。** 词汇表会变长，已有 token 不受影响 ——
  [`server/src/auth.rs`](../server/src/auth.rs) 今天有 **32** 个 capability，而这个数字不是契约。
- **[已定]** **加一种事件类型**，以及给一个「客户端应当当成开放集合」的枚举加一变体。
- **[已定]** **加一个可选头**，以及给一个文档标注为开放集合的字段加一个取值。

## 3. 小版本里不允许的变更

以下每一条都需要 **major** 版本，因而需要 §6 的迁移路径：

- **[已定]** **改已有字段的含义** —— 同名、同类型、不同行为。
- **[已定]** **删字段、删端点、删 capability、删事件类型。**
- **[已定]** **改一条 URL 的语义**，或改某条路径所服务的方法。
- **[已定]** **改一次已文档化失败所携带的错误 `code`。** 按 `code` 分支正是这个字段的用途，所以一个
  含义变了的 code 就是破坏性变更 —— 哪怕状态码没变。
- **[已定]** **改一个审计事件的 `action` 字符串或其 `detail` 的含义** —— 链会被不是在这里写的工具读取，
  一个被改写的含义会让历史说谎。

## 4. 弃用

- **[已定]** **弃用要公告，不能靠人踩。** 一个被弃用的端点会在应答里带 `Deprecated` 头，写明替代者
  （若有，还写明它将在哪个版本被移除）。
- **[已定]** **至少活一个大版本。** 弃用它的那个 major 版本里不做移除；最早的移除也要等下一个。
- **[已定]** **文档同步写明。** [`control-plane-api.zh-CN.md`](control-plane-api.zh-CN.md) 对应那行
  标上 `deprecated since vX.Y`，于是表与头不可能互相矛盾。
- **[已定]** **被弃用的东西照常工作。** 「弃用」从不意味着「更慢」「拒绝」或「悄悄不一样」。

## 5. 版本

- **[已定]** **路径前缀承载协议的 major 版本。** 整个 v0.x 线用 `/v0/`，从 v1.0 起用 `/v1/`（这遵循
  [`control-plane-api.zh-CN.md`](control-plane-api.zh-CN.md) §7 已经写下的那句：v1.0 冻结 API，前缀变为
  `/v1/`）。
- **[已定]** **v0.x 什么都不承诺。** 在 v0.x 内，破坏性变更不发前缀就上，客户端必须容忍它。v0.x 的集成
  方钉的是 RiscDom 的**版本区间**，不是 API 版本。
- **[已定]** **从 v1.0 起，semver 严格执行**：`MAJOR.MINOR.PATCH`。一个小版本只可含 §2 的变更；一个大
  版本可含 §3 的，并自带迁移。
- **[已定]** **包版本与协议版本不是同一个数。** 1.3.0 的发行版说的仍是 `/v1/`；前缀只在协议破坏时才动。

## 6. 数据迁移

**规矩。** **[已定]** 每一种持久化格式都把**版本标记放在它的首字段**，于是读方在读别的东西之前就知道
自己手上是什么。做不到这一点的格式（SQLite 数据库）把标记放在自己的元数据表里一行，与 schema 在同一个
事务里写下。

- **[已定]** **打开即迁移。** 没有需要记住的工具、没有要传的旗标：在新版本上启动的节点会打开旧数据并
  迁移它。这就是 [decisions.zh-CN.md §14](decisions.zh-CN.md) 那句「数据迁移是自动的」的意思 —— 另一条路
  （要求用户手动跑迁移的升级）是一种会被跳过的升级。
- **[已定]** **新读旧：允许。** 读方先迁移、再读。在写下任何东西之前，它会为即将改动的文件留一份
  **`.bak` 副本**，于是一次出错的迁移有一条已知的回头路。
- **[已定]** **旧读新：拒绝。** 较旧的构建遇到较新的格式时返回 **`Err(DataTooNew)`**，并且不做别的：
  不得部分读、不得只读它认识的字段而忽略其余、不得静默降级或改写。一个只答出较新格式一半真相的节点，
  比一个明确拒绝的节点更坏 —— 拒绝可诊断，半读不可。
- **[已定]** **迁移不可逆。** 没有「迁回去」；`.bak` 副本是逃生口，[`riscdom-backup`](decisions.zh-CN.md)
  （§19）也是 —— 它的包是可搬走的单位。
- **[已定]** **每种格式一个版本标记，全列在这里。** 下表就是全部清单；新增一种持久化格式，就在创建它的
  同一个批次里加上它的行。

| 格式 | 位置 | 今天的版本标记 | v1.0 的动作 |
|---|---|---|---|
| `settings.json` | `<data-dir>/settings.json` | `version` = `SETTINGS_VERSION`（自 v1.0 M2b-1 起为 **2**） | **第一次真迁移发生在 v1.0 M2b-1**：v1 文件（LLM 配置当时根本不落盘）在打开时迁移为 **2**，并带一张空的 per-executor `llm_configs` 表 —— 不猜任何东西 —— 迁移前的字节留作 `settings.json.bak`；而**更新的**文件以 `data_too_new` 被拒绝（不应用、不写入） |
| run 指纹 | 每条 run 记录之内 | `FINGERPRINT_SCHEMA_V1` = `riscdom.run.fingerprint.v1`（[`audit/src/run.rs`](../audit/src/run.rs)） | v2 指纹是一个新的标记值，绝不是改写 v1 记录 |
| 审计库 | `<data-dir>/audit.db`（SQLite） | 只有 schema DDL —— **尚无显式版本行** | 标记行随 §6 的迁移工作落地，在冻结之前 |
| 会话库 | `<data-dir>/sessions.db`（SQLite） | 只有 schema DDL —— **尚无显式版本行** | 同上 |
| 凭据文件 | `<data-dir>/token` | 无：一行 hex，只做形状检查 | 手工放置的 token 永不被改写；v1.0 的 `node.key` 自带标记 |

- **[已定]** **标记不是对其他节点的承诺。** 不同版本的两个节点只共用协议允许共用的部分；较旧的那个
  拒绝较新的文件，而不是去猜。

## 7. 升级路径

- **[已定]** **就地。** 安装包覆盖安装；不重装、数据目录不搬家（decisions §14）。
- **[已定]** **跨大版本必须逐步。** 不得跳过大版本：1.x → 3.x 要走 2.x。每一步带上它需要的迁移（§6），
  该步的迁移工具随那一步的发行说明提供。
- **[已定]** **迁移是自动的** —— 见 §6。「逐步」这条针对的是*数据*：每个大版本的迁移都假定上一个大版本
  的结果已经在了。
- **[已定]** **成文流程是 [`docs/upgrade.md`](upgrade.zh-CN.md)** —— [decisions §14](decisions.zh-CN.md)
  已经点名的那个位置。**它目前还不存在**；它会在 v1.0 之前落地，在那之前本节就是流程。

## 8. 不承诺什么

- **[已定]** **不承诺 0.x → 1.0 无痛。** v0.x 什么都不承诺（§5）；不过 1.0 的迁移仍然会被写出来（§6），
  且先留一份 `.bak`。
- **[已定]** **不支持跳过大版本。** 从 1.x 直接升 3.x 会被拒绝，而不是被尝试。
- **[已定]** **私有的内部 API 一概不在本文覆盖范围之内。** 没有被文档写下的、也不在 `pub use` 面里的
  东西，本文对它一个字都不说。
- **[已定]** **macOS / Linux 的包与 Windows 安装包遵循本文，而不是各自的规矩。** 一个与本文不一致的包
  就是一个 bug。
