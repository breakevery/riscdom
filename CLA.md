# RiscDom Contributor License Agreement (CLA)

**Version 1.0 — dated 2026-09-19.**

> **Status.** This document states the contribution process RiscDom uses and the licence grants
> that process relies on. It is **not legal advice**, and it takes effect for a contribution only
> once the Project Owner has confirmed it. The English text is the authoritative one; the
> [Chinese version](CLA.zh-CN.md) is a reference translation.

By signing this agreement (see §8) you accept the following terms for every Contribution you make
to the Project.

## 1. Definitions

- **"Project"** — the RiscDom repository and the work distributed from it.
- **"Project Owner"** — the copyright holder of the Project; today that is the GitHub account
  `breakevery`.
- **"You"** — the individual, or the legal entity on whose behalf an individual acts, making a
  Contribution.
- **"Contribution"** — any original work of authorship you intentionally submit to the Project for
  inclusion in it: source code, tests, documentation, configuration, and patches, diffs or file
  attachments in issues and pull requests. It does **not** include material you clearly mark as
  "not a contribution" when you submit it, and it does not include things you merely discuss.

## 8. How to sign

1. Open the pull request that contains your Contribution.
2. Post a comment containing exactly this sentence, in English:

   ```text
   I have read the CLA Document and I hereby sign the CLA
   ```

   (In Chinese, for reference: 我已阅读 CLA 文档，并在此签署该 CLA。)

3. The CLA Assistant bot records the signature in
   [`signatures/version1/cla.json`](signatures/version1/cla.json) and updates the pull request's
   check. **A pull request whose author has not signed is not merged.**
4. If you contribute as an employee or on behalf of a company, contact the Project Owner through
   the repository's issue tracker before your first pull request.

The sentence itself is **not translated**: the bot matches the English text exactly.

## 9. Small contribution exception

A trivial change — a typo, a broken link, a comment or wording fix, or a comparably small
documentation correction — may be accepted without a signature, at the Project Owner's discretion.
Anything larger, including any change to code or to the behaviour of the Project, needs a recorded
signature.
